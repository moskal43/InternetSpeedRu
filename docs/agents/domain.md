# Доменная документация

Правила использования доменной документации репозитория инженерными skills при изучении кодовой базы.

## Что читать перед изучением кодовой базы

- **`CONTEXT.md`** в корне репозитория; или
- **`CONTEXT-MAP.md`** в корне репозитория, если он существует: файл указывает на отдельные `CONTEXT.md` для каждого контекста. Читать каждый контекст, относящийся к задаче.
- **`docs/adr/`**: читать ADR, затрагивающие область предстоящей работы. В multi-context репозиториях также проверять `src/<context>/docs/adr/` на наличие решений, относящихся к конкретному контексту.

Если этих файлов не существует, продолжать работу без предупреждений и не предлагать создать их заранее. Skill `/domain-modeling`, вызываемый через `/grill-with-docs` и `/improve-codebase-architecture`, создаёт их по мере необходимости при уточнении терминов или принятии решений.

## Структура файлов

В этом репозитории используется single-context структура:

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-example-decision.md
│   └── 0002-another-decision.md
└── custom_components/
    └── <integration_domain>/
```

Для сравнения, multi-context структура определяется наличием `CONTEXT-MAP.md` в корне:

```text
/
├── CONTEXT-MAP.md
├── docs/adr/                          ← общесистемные решения
└── src/
    ├── context-a/
    │   ├── CONTEXT.md
    │   └── docs/adr/                  ← решения конкретного контекста
    └── context-b/
        ├── CONTEXT.md
        └── docs/adr/
```

## Использование терминов из глоссария

Когда результат работы называет доменное понятие — в заголовке issue, предложении по рефакторингу, гипотезе или имени теста — использовать термин в том виде, в котором он определён в `CONTEXT.md`. Не заменять его синонимами, от которых глоссарий явно отказывается.

Если нужное понятие отсутствует в глоссарии, проверить, действительно ли необходим новый термин. Если пробел реален, зафиксировать его для `/domain-modeling`.

## Конфликты с ADR

Если предлагаемая работа противоречит существующему ADR, явно указать конфликт, а не отменять решение молча:
