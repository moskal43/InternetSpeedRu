# Миграция с официальной Iperf3-интеграции

InternetSpeedRu не изменяет конфигурацию официальной Iperf3-интеграции и не
мигрирует её автоматически. Выполните переход вручную, сохранив старую настройку
до завершения сравнения.

## 1. Установите параллельно

Установите InternetSpeedRu через HACS custom repository и настройте его через
интерфейс. Не удаляйте существующую секцию `iperf3:` из `configuration.yaml` и не
отключайте связанные automation. Две интеграции могут временно публиковать свои
сущности параллельно; не запускайте их тяжёлые тесты одновременно.

## 2. Сравните результаты

Выберите в InternetSpeedRu manual-сервер, сопоставимый со старой настройкой, или
зафиксируйте фактически выбранный Auto-сервер по статусной сущности. Выполните
несколько замеров в одинаковых условиях и сравните download/upload. Latency в
InternetSpeedRu — медиана TCP connection probes к Iperf3-порту, поэтому её нельзя
напрямую приравнивать к ICMP ping или иной старой метрике.

## 3. Переключите dashboard и automation

Запишите entity IDs пяти новых сущностей из карточки устройства InternetSpeedRu.
Вручную замените ссылки на старые Iperf3 entity IDs во всех dashboard-карточках,
template, script и automation. Для ручного запуска используйте новую кнопку
InternetSpeedRu; для регулярных запусков настройте встроенный интервал и удалите
дублирующий внешний trigger только после проверки нового расписания.

## 4. Удалите legacy YAML

Когда dashboard и automation работают с InternetSpeedRu, удалите секцию старой
официальной Iperf3-интеграции из `configuration.yaml`, проверьте конфигурацию и
перезапустите Home Assistant. Затем убедитесь, что старые сущности больше не
используются в dashboard, automation, script или template.

## История

Recorder history старых сущностей **не переносится** в новые сущности
InternetSpeedRu. У них другие unique IDs, а автоматическое объединение истории
не выполняется. Старую Recorder history можно оставить для просмотра в пределах
срока хранения; InternetSpeedRu начнёт собственную непрерывную историю с первого
успешного полного замера.

Если в ходе перехода результат выглядит неверно, верните dashboard/automation на
старые entity IDs и оставьте legacy YAML до выяснения причины.
